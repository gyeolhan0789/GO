### 3.4 Prod Backend 배포

운영 배포는 `backend/Jenkinsfile.prod`의 Jenkins pipeline 사용을 기본으로 한다.

Jenkins 파라미터:

| 파라미터 | 설명 |
| --- | --- |
| `DEPLOYMENT_MODE=validation` | 18080/18443 임시 포트에서 Docker Nginx 후보 검증. 운영 트래픽 전환 없음 |
| `DEPLOYMENT_MODE=production` | 80/443 Docker Nginx cutover, canary 10%, canary 100%, stable promotion 진행 |
| `CURRENT_STABLE_REVISION` | 기존 이미지에 Git revision label이 없을 때 운영 중인 stable Git SHA 입력 |

Jenkins Credentials:

| Credential ID | 용도 |
| --- | --- |
| `prod-db-password` | 운영 MySQL app user password. 정의 필요 |
| `prod-db-root-password` | 운영 MySQL root password. 정의 필요 |
| `prod-jwt-secret` | 운영 JWT secret. 발급/생성 필요 |
| `prod-firebase-credentials` | 운영 Firebase service account JSON. 발급 필요 |

운영 배포 특이사항:

- `wecandoit-edge` Docker network가 필요하다.
- prod MySQL/Redis 컨테이너는 먼저 healthy 상태여야 한다.
- 운영 Nginx는 Docker Nginx를 사용하며, 최초 cutover 시 Host Nginx의 80/443 포트를 비워야 한다.
- production 모드는 canary 10% 전환 후 60초 관찰, 5xx 비율, 평균/최대 응답 시간, container error log를 확인한다.
- 최종 stable promotion 전 Jenkins 수동 승인 단계가 있다.
- Flyway는 기본적으로 canary에서 실행하고 stable은 비활성화한다.
- schema 변경 전 운영 DB 백업이 필요하다.

## 5. 배포 특이사항

### 5.1 Backend dev

- `backend/` 또는 `infra/monitoring/` 변경이 없으면 Jenkins dev CD는 `NOT_BUILT`로 종료한다.
- Jenkins 컨테이너에서 Docker outside of Docker 방식으로 compose를 실행한다.
- Firebase service account JSON은 Jenkins file credential로 받아 `backend/secrets/firebase-service-account.json`에 복사한다.
- dev backend는 `127.0.0.1:8081`에 바인딩되고 Nginx `/dev/`로 프록시된다.
- dev WebSocket은 `wss://i15a506.p.ssafy.io/dev/ws`를 사용한다.

### 5.2 Backend prod

- 운영 배포는 canary 구조다.
- stable container: `wecandoit-backend-stable`, host port `127.0.0.1:8080`.
- canary container: `wecandoit-backend-canary`, host port `127.0.0.1:8082`.
- management port `9091`은 컨테이너 내부 health check 용도다.
- Nginx upstream은 `stable-only`, `canary-10`, `canary-only` 중 하나로 전환된다.
- canary container가 Flyway migration 실행자다.
- stable container는 기본적으로 Flyway disabled, Hibernate DDL `none`이다.
- 새 schema 변경 전 DB 백업을 반드시 수행한다.

### 5.3 Nginx

- prod `/ws`와 dev `/dev/ws` 모두 WebSocket Upgrade 헤더가 필요하다.
- TLS 인증서는 host의 `/etc/letsencrypt`를 Nginx 컨테이너에 read-only mount한다.
- Admin UI는 host `/var/www/wecandoit-admin`을 read-only mount한다.
- Certbot challenge 경로는 `/var/www/certbot`이다.

### 5.4 AI

- Jenkins AI pipeline은 현재 실제 컨테이너 배포를 하지 않는다.
- dev/prod AI는 개발자 워크스테이션 실행 + SSH reverse tunnel 방식이다.
- AI 서버 `.env`에는 Gemini 관련 값을 직접 정의해야 한다.

### 5.5 Frontend

- `.env` 값을 바꾼 뒤에는 Metro cache를 지우고 다시 시작해야 한다.

```bash
npm start -- --reset-cache
```

- Android release는 현재 debug keystore를 사용한다. 실제 운영 배포 시 별도 release keystore 발급 및 Gradle signing 설정이 필요하다.
- Google Maps API key는 `frontend/android/local.properties`에만 둔다.
- Firebase Android 설정 파일 `google-services.json`은 Firebase Console에서 발급받아 배치한다.

## 7. 외부 서비스 정보

### 7.1 Google OAuth

용도:

- 모바일 Google 로그인
- 백엔드 id token 검증

필요 작업:

1. Google Cloud Console에서 OAuth Client 생성.
2. Web Client ID 발급.
3. `frontend/.env`의 `GOOGLE_WEB_CLIENT_ID`에 정의.
4. 백엔드 `application-*.yml`의 `oauth.providers.google.client-id`와 같은 값으로 맞춘다.

참고:

- 새 프로젝트로 포팅할 때 Web Client ID 발급 필요.
- Client Secret을 사용하는 구조는 현재 코드에서 확인되지 않는다.

### 7.2 Kakao Login

용도:

- 모바일 Kakao 로그인
- 백엔드 id token 검증

필요 작업:

1. Kakao Developers에서 애플리케이션 생성.
2. Native App Key 발급.
3. 필요 시 `frontend/android/local.properties`의 `KAKAO_NATIVE_APP_KEY`에 정의.
4. 백엔드 `application-*.yml`의 `oauth.providers.kakao.client-id`와 일치하도록 설정.
5. Android package name, key hash, redirect scheme 설정.

참고:

- 새 프로젝트로 포팅할 때 Native App Key 발급 필요.

### 7.3 Firebase / FCM

용도:

- 모바일 push notification
- 백엔드 FCM 발송

필요 작업:

1. Firebase Console에서 프로젝트 생성.
2. Android 앱 등록.
3. `google-services.json` 발급 후 `frontend/android/app/google-services.json`에 배치.
4. Firebase Admin SDK service account JSON 발급.
5. dev/prod Jenkins Credentials에 각각 `dev-firebase-credentials`, `prod-firebase-credentials`로 등록.
6. 배포 시 `backend/secrets/firebase-service-account.json`로 mount되도록 한다.

참고:

- Firebase Admin SDK service account JSON 발급 필요.

### 7.4 Google Maps

용도:

- 산책 경로 지도 표시.

필요 작업:

1. Google Cloud Console에서 Maps SDK for Android 활성화.
2. Android API key 발급.
3. `frontend/android/local.properties`에 `MAPS_API_KEY=<발급 필요>`로 정의.

참고:

- Android API key는 앱에 포함될 수 있으므로 package/signature 제한을 설정한다.

### 7.5 Gemini API

용도:

- AI 서버의 미션 이미지 판정 fallback/보조 판정.

필요 작업:

1. Google AI Studio 또는 사용하는 Gemini API 제공 환경에서 API key 발급.
2. AI 서버 `.env`에 다음 값 정의.

```env
GEMINI_API_KEY=<발급 필요>
GEMINI_MODEL=<정의 필요>
GEMINI_BASE_URL=<정의 필요>
```

참고:

- `GEMINI_API_KEY` 발급 필요.

<a id="db-dump"></a>
## 8. DB 덤프 파일 최신본

포팅용 DB 덤프 파일은 다음 경로에 둔다.

```text
exec/db/latest-wecandoit-dump.sql
```

현재 포함된 덤프는 저장소의 Flyway 마이그레이션 `V1`부터 `V7`까지 적용한 최신 스키마에 `backend/src/main/resources/db/local/data.sql` 시드 데이터를 넣어 생성한 포팅용 덤프이다.

운영 서버에서 운영 데이터 dump를 다시 생성해야 하는 경우:

```bash
mkdir -p exec/db
docker exec wecandoit-mysql-prod \
  mysqldump -uroot -p"$DB_ROOT_PASSWORD" \
  --databases wecandoit \
  --single-transaction \
  --routines \
  --triggers \
  --events \
  --default-character-set=utf8mb4 \
  > exec/db/latest-wecandoit-dump.sql
```

dev DB dump 생성 예시:

```bash
mkdir -p exec/db
docker exec wecandoit-mysql-dev \
  mysqldump -uroot -p"$DB_ROOT_PASSWORD" \
  --databases wecandoit \
  --single-transaction \
  --routines \
  --triggers \
  --events \
  --default-character-set=utf8mb4 \
  > exec/db/latest-wecandoit-dev-dump.sql
```

dump 복구 예시:

```bash
docker exec -i wecandoit-mysql-prod \
  mysql -uroot -p"$DB_ROOT_PASSWORD" < exec/db/latest-wecandoit-dump.sql
```

확인 사항:

- dump 생성 전 현재 schema migration 버전과 `flyway_schema_history`를 확인한다.
